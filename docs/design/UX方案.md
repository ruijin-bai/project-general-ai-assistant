# 首期 UX 方案

版本：V0.1；日期：2026-10-08（Africa/Lagos）。基线：[PRD V1.6](../product/PRD.md)第1、3、5、6、10–12节。

状态：以下保留纸面设计范围与建议；后续本地单经办工作区已实现并通过主路径、刷新续办、暂停/接手及桌面/窄屏浏览器检查，具体证据见工程验证记录。员工私有与执行者正式协同界面未实现，真实模型与业务验收未完成。Muse式目标委托、持续推进、透明活动、可用成果和用户控制仍为硬约束，不据局部界面扩大正式业务范围。

## 1. 输入事实与范围

- **已确认**：综合部实际为经理安排工作、办理人员执行办理；主流程按一个综合经办主体考虑。经理的原安排职责保留，真实身份分别记录，不新增经理审批、强制交接或两个必经工作盘。
- **已确认**：现用微信、口头、在线Excel；用户定性痛点为“繁琐”。厨师为中国人，司机、清洁工、帮厨等为属地员工。
- **已确认**：当前为竞赛阶段，数据库须轻量、好部署。UX只保留所选事项必要输入、状态、来源和成果，不增加ERP式表格管理或双维护；数据结构与部署技术交架构取舍。
- **待验证假设**：从不同渠道整理、重复转录、解释、补问和追状态可能造成负担；没有完整真实流程、频次、耗时或收益样本。
- **当前设计范围**：员工私有目标工作区、一个综合经办持续工作区、执行者极简任务视图，共用同一事项及授权边界。员工不必先使用新入口；经办可从获授权的现有文字或实际口头转录开始。
- **业务待核**：审批渠道/批准证据、资源/派遣口径、饭点/触发/截止均未知时，只交准备内容和待核项，不能交“可执行安排”。语言、设备、账号/代录、弱网、送达渠道仍按Q-010/013/014核定。

## 2. 主路径与共同信息结构

`表达目标 → 整理已有事实与阻断缺项 → 在授权能力内准备/持续推进 → 等待真人或回执 → 可编辑可用成果 → 修改续办、暂停或接手`

目标委托位于主要工作区。业务分类只做筛选，不先进入管理中心再找功能；不以四业务门户加侧栏聊天交付。准备目标完成与业务办结分开：清单已准备好，仍可等待原安全结果、真实派遣或实际出返。

| 同一事项内的区域 | 必须可见的信息与动作 | 减少的负担 |
| --- | --- | --- |
| 目标与事实 | 原话、当前修订、本人/经办已确认事实、来源、未核字段；可直接改具体事实 | 不重复描述或跨表重填 |
| 成果 | 可编辑准备内容、缺项清单、安排候选或真实已核安排；编辑、保存、复制 | 少转写，得到可继续用的结果 |
| 独立业务状态 | 安全审批、车辆、实际出返、餐次各有状态与依据；未知明确显示 | 少追问，不被总“完成”误导 |
| 等待与下一步 | 等谁/什么来源、原因、本人是否需动作；没有已确认对象则写“责任对象待核” | 少猜当前卡在哪里 |
| 活动 | 实际输入、准备、修改、授权动作、失败和反馈记录；按需展开 | 少翻消息，能解释当前结果 |
| 用户控制 | 修改事实、暂停代办、继续、人工接手；取消行程另列 | 遇变化或故障仍能续办 |

活动只记可观察动作及其来源，不展示模型内部思维，不用反复生成文本冒充推进。普通进展合并；只突出阻断缺项、冲突、重要变化和必要决定。除关键事实集中确认、真实业务决定等必要节点，不每步弹确认，不要求经理再次批准准备成果。

## 3. 三种授权视图的文字线框

### 3.1 员工私有目标工作区

```text
[项目与本人身份]                                      [我的事项]
今天想让助理帮你办什么？
[一句话目标________________] [选取授权文字/材料] [开始准备]

需我处理：只列本人阻断缺项或需本人决定
我的进行中事项：目标 / 当前进展 / 等待谁 / 下一步

打开同一事项
  目标与当前事实       [修改]
  可用成果             [编辑] [保存] [复制]
  安全 | 车辆 | 实际出返 | 餐次（各自状态）
  等待原因与下一步     [补充信息/登记本人真实反馈]
  活动与来源           [展开]
  [暂停代办] [人工接手]；行程取消另列
```

目标和私人材料默认私有。需要经办承接时，沿核定的授权范围提供必要事实与准备内容，不自动分享整段聊天、全部附件或同行私人材料。简单本人反馈直接操作，不等待AI写一篇回复；“实际返回”不要求重填原行程。经理身份不自动获得员工私有内容。（F-001–003/014/017；AC-001–007/029/039）

### 3.2 综合经办持续工作区

```text
[项目 / 当前真实操作者 / 授权范围]          [查找事项或已有来源]
告诉助理要准备、核对或跟进什么
[目标或授权原话____________] [添加已有来源] [开始准备]

需我处理：缺项 / 冲突 / 来源变化（打开即到问题处）
持续事项：正在准备 | 等待反馈 | 可用成果 | 已暂停
  每项：目标 / 当前修订 / 等待对象与原因 / 下一步

打开事项
  [成果与事实] [活动与来源]（同一事项，不另建多套业务表）
  准备成果 + 独立业务状态 + 可用下一步
  [编辑并保存] [复制所选内容] [登记实际反馈/引用]
  [暂停代办] [继续] [人工接手]
```

经理安排可成为获授权目标的来源，保留安排人、实际记录人与操作者；不要求经理先登录、转派、再次批准才开始。经办从授权微信文字、口头实际转录或Excel所选记录开始即可，不强迫员工迁移所有沟通渠道。计数若使用，须打开权限内唯一事项明细并标范围/时点；未知或未接入不填0，不用装饰趋势图占主区。（F-001–003/011/014–017；AC-003–007/029/032–035/038–039）

### 3.3 执行者极简任务视图

```text
[本人身份]  我的任务
任务：需要做什么
地点 / 时间 / 范围 / 必要联系人 / 注意事项
当前授权安排与变更；需要等待时明确原因
[已接受] [有障碍] [登记实际出发/返回]
必要说明：____________
反馈结果与状态：已保存 / 保存失败待重试
```

首期以司机参与出行的必要信息为例，只在真实授权安排及任务范围内提供执行入口；演练中始终标“模拟反馈”，不记作真实出返。无有效安全批准不提示“可以出发”，但若已有实际出行事实，允许授权记录真实反馈并列安全待处置，不补造批准。此视图不提供员工护照、审批附件、私人聊天或全部门看板。没有账号/通道时由经办记录实际口头反馈，区分反馈人与记录人，不假装司机本人点击。厨师、清洁工、帮厨未来可复用这一信息层次，具体业务交互未在本稿展开。（F-003/005/013/017；AC-006–008/012/030/039）

## 4. 已有渠道与一次源输入的准备路径

下列均为待实现建议，不表示当前已有识别、导入或连接能力。

| 现有来源 | 最低准备路径 | 复用与交付边界 |
| --- | --- | --- |
| 微信文字 | 有权者粘贴选定文字，或经办实际摘录；来源区带原陈述人、原信息时间/已知上下文、记录人，未知不编造 | 保留原话并提取候选；不自动读群、取联系人、发消息。复制成果只记“已复制”，不能记已发、送达或承接 |
| 口头 | 经办按实际听到的内容转录，明确“口头转录”与陈述人/记录人；仅对阻断歧义补问 | 原话/转录与AI整理分开。无已验语音能力不称录音已转写；简单真实反馈无需AI或经理再批准 |
| 在线Excel | 经办提供授权导出快照、选中单元格文字或获授权原记录引用；展示表/范围/期间/读取时点，字段或读取能力不足时待核 | 先预览已读取范围、候选映射与差异，再由有权者采用关键事实；不承诺自动同步/回写，不将缺行当删除、空白当0 |

同一源输入支撑同一事项的安全准备、用车准备与餐次核对，各自引用当前已确认修订，不能让用户分别再填。另一目标确需复用时由用户选择有权来源与必要事实，不自动把私人上下文扩散；明确来源/时点和适用性变化，只确认需要变更的关键项。无变化的事实不再逐项确认。

Excel作为被指定的权威记录时，交付可复制的字段/差异清单供实际维护人按原流程使用；本系统保存事项及来源引用，不另建与Excel要求双边手工维护的业务总账。复制、保存、实际外部改表和核回结果分别记；唯一权威表、维护者和写回能力未核时显示待核。（F-001/003/011/013/014/017；AC-001–003/028–030/032–033/042；Q-001/010–013）

## 5. 出行准备演练：完整而不冒称真实

**假设场景，仅供设计审查；不是用户提供的真实样本，不证明实际流程、审批、安排或执行。** 演练页及复制成果均标“流程演练/准备草稿”。示例：“某日14:00去机场接人，预计17:00返营，需要用车，晚餐保留。”日期、同行与接人信息按目标实际缺项补问；例子不设项目正式饭点或资源参数。

| 阶段 | 用户看到/可做什么 | 未核时的退化与恢复 |
| --- | --- | --- |
| 一次表达 | 原话保留，出现可改候选事实；只集中核关键事实与联动影响 | 日期/地点/同行等阻断歧义就地补；不要求填写三套表 |
| 准备 | 同一事项交安全准备内容、用车需求和餐次例外；成果可编辑保存复制 | Q-002/004/005未核：显示“原安全渠道待核／车辆资源待核／餐次规则待核”；不猜审批人、车、减餐或饭点 |
| 持续与等待 | 说明已准备、等待什么依据、下一步；关闭重开继续同一修订 | 无通道就显示“准备内容可复制，真实提交未登记”；不能声称已外发或后台替人办理 |
| 模拟引用与反馈 | 隔离模拟分支可演示状态如何引用来源、时间和登记人 | 模拟批准/派遣/反馈只记演练，不进入真实业务记录；批准、派遣、出返、餐次仍各自显示 |
| 变更续办 | 改预计返营时间，显示受影响差异和需重核项，保留原修订及人工修改 | 原批准适用范围和餐次规则未知，标待核，不沿用旧批准或自动扣餐 |
| 暂停或接手 | 暂停未来AI动作；成果仍可编辑复制并人工继续；继续时重核变化 | “申请取消行程”另列；只准备取消内容时不称已取消，不把未知取消当车辆释放 |

准备成果已可用即可显示“准备完成，业务待核”。正式出行可执行及业务关闭须等相关Q与真实来源核定，本演练不替代这一门槛。仅当后续得到真实授权业务输入与能力时，才按PRD第6节核详细流程。（F-004–007；AC-008–019）

竞赛演示的重点是完整看到“一次目标 → 准备/等待 → 可用成果 → 修改续办/暂停接手”；未配置模型、未接入渠道、口径未知均须真实可见。隔离演练可演示状态变化，但不以假运营看板、虚构批准/出返/餐次数字或未测减负效果填充页面；纸面演练与未来软件演示均不计真实业务样本。

## 6. 状态、校验与恢复

| 状态/问题 | 可观察反馈与动作 |
| --- | --- |
| 空 | 给一句真实目标例子与输入入口；不灌示例待办或运营数字 |
| 整理/处理中 | 显示正在执行的可观察步骤与已保存部分；可暂停或接手，避免无限加载 |
| 待补/校验不通过 | 具体到缺字段或时间含义，说明阻断哪项准备；就地修改，保留已输入内容；规则未知与输入错误分开 |
| 等待真人/依据/能力 | 等待对象、原因、来源时点与下一步；无对象就待核，不假装持续执行；普通等待不反复通知 |
| 未读取/部分读取 | 列已读与未检查范围，上传不等于识别；人工补充文字仍可继续 |
| 可用成果 | 标准备草稿/真实已核安排、版本和适用范围；可编辑保存复制，不混称正式批准或业务完成 |
| 禁用动作 | 给具体原因和替代路径，例如缺有效批准不能确认可执行安排，但可继续整理用车需求；不禁用真实事实登记 |
| 模型/网络/预算失败 | 保留源输入、人工修改和已发生事实，显示成功部分与待处理部分；仅重试未成功步骤或人工接手，不擅自换外部模型 |
| 保存/并发冲突 | 明示未保存或版本冲突，保留当前编辑供核对，禁止旧异步覆盖新修订；确认资源时冲突不得产生两份有效安排 |
| 无权限/撤权 | 不显示受限内容及派生附件，停止相关未来动作；说明可按原授权流程处理，不靠职位自授权 |
| 暂停/取消/重开 | 暂停代办不等于取消业务；取消未核保持待确认，不删除已出返/备餐/实供；新证据续办原事项并保留历史 |

返回、刷新或切换事项须恢复正确对象及保存状态；换账号不残留前一账号内容。需要联系/外发时先有核定对象、必要范围与真实能力；无通道只准备，不称已送达。

## 7. 视觉与窄屏原则

保留参考图的蓝白层次、明确选中导航、短标题和少量常用任务例子。主区依次突出目标、需我处理、持续进展和成果；缩减大欢迎横幅、宣传图、时钟和无实际用途图表。业务分区只做次级筛选，避免菜单、中心卡和入口重复。

桌面可用简短事项列表加当前事项工作区；活动/来源按需展开，不常驻长聊天占主区。窄屏按单列展示当前任务、成果与简单反馈，保留修改/暂停/接手，不缩小桌面多栏照搬。重要状态用文字并配色，按钮有明确标签；焦点、键盘操作、持续错误提示与目标设备可用性列为后续实际验证。语言、语音及设备方式待核，不能从国籍推定或宣称已经支持。

## 8. 可观察验收与架构交接

以下是后续验收映射，**均未执行，未标通过**。纸面演练只能评审信息与恢复路径；跨账号、并发、刷新、输入识别和真实流程需实现后用相应证据验证。

| 要观察的行为 | 关联F/AC |
| --- | --- |
| 一次目标及源输入生成同一事项；关键事实确认后跨准备成果引用同一修订，无重复填三表 | F-001/007；AC-001–003 |
| 主区可观察持续事项、成果、等待对象与下一步；准备完成不标业务完成，重开仍可编辑续办 | F-002/014/017；AC-004–005/029 |
| 员工私有上下文与执行者必要任务隔离，实际身份可核；经理安排不等于安全批准，分享/复制也受权限约束 | F-003；AC-006–008/028 |
| 未核规则及原渠道结果不造可执行结论；批准、派遣、实际出返、餐次分开，有安全例外仍如实登记 | F-004–006/011；AC-008–015 |
| 修改只重核受影响内容；取消未知不释放资源，不删除真实事实；跨端冲突、重复和部分失败可恢复 | F-007/016；AC-011/016–019/029/035/042 |
| 未读取范围可见，文字替代路径成立；复制不等于外发，Excel导入对照不要求双维护 | F-011/013/017；AC-030/032–033 |
| 普通进展合并、待办计数有唯一明细和口径，未知不为0；暂停和预算失败有人工出口 | F-015/016/028；AC-034–035/038/041 |
| 窄屏反馈、标签焦点、空/加载/错误/无权限及刷新返回可用，换账号无旧内容回写 | F-001/014/017；AC-039 |

架构需承接共用事项、修订/来源、成果、真实身份/权限、独立业务状态、活动/等待、保存冲突及有限动作边界；UX不指定其技术实现。现有形态和F/AC可复用，工作区、事项详情和极简执行视图为待建设页面结构。待产品与真实责任人核定所选范围、来源/权限、Q-002–006及Q-010–016后，才细化正式出行操作；Q-017用于后续真实净减负验证，不以纸面可读性替代实际效果。
