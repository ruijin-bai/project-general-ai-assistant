# 轻量本地启动

需要 Python 3.11 或更新版本。应用使用标准库、SQLite、原生网页，不需要安装第三方Python包、Node服务或独立数据库。仅支持本机单实例，默认监听127.0.0.1；当前版本不开放公网。

## 首次运行

解压应用包，在目录打开终端：

```powershell
python -X utf8 run.py
```

打开 http://127.0.0.1:8765。默认是单经办隔离预览；运行数据在`.runtime/assistant.sqlite3`，无内置业务数据。退出用终端Ctrl+C，保留此目录即可再次启动续办。端口被占用时加`--port 8770`；保持一个数据目录只运行一个实例。

## 独立本地账号

首次管理员必须在本机交互终端自行设密码：

```powershell
python -X utf8 run.py --setup-admin my-admin
python -X utf8 run.py --multi-user
```

管理员只管理账号，不自动获得私人业务材料。由管理员按实际职责建立个人账号；本人凭激活码设置密码。菜单、执行者、综合经办使用各自账号，不能共用身份。旧单人事项升级前自动备份，并保留旧归属；需要实际经办明确认领，不自动转归。

## 备份和搬迁

先Ctrl+C停止这个数据目录的实例，再运行：

```powershell
python -X utf8 run.py --backup
```

一致SQLite备份存入`.runtime/backups/`，执行后会打印具体文件。若已保存原附件，原始字节与引用同在数据库中，一致备份包含原件；无需另建附件存放服务。原件只保存和下载，内容未读取或识别。搬迁本机工程工作区时，在服务停止后保存整个`.runtime`目录；恢复到新的应用目录后启动。不要用空目录覆盖现有运行数据；不把个人账号、来源或模型配置夹入应用包。

## 模型与实际业务

默认模型未启用；已有模板、结构整理、手工编辑、可靠计算和跟进可用。交融使用项目明确指定的`.env`配置及固定许可路线，凭据由本人配置，只有显式选择模型整理才发送本事项输入。未接微信、在线表或真实业务系统。批准、派遣、供餐、签发、支付与真实处理结果分别核对；工程演练不证明现场效果。

包内`.env.example`默认禁用、无凭据。需要使用已获许可的交融模型时，由本人复制为本项目`.env`，填写自己的许可密钥，再明确改启用标志并重启本实例；不把`.env`发给他人或夹进应用包。模型输入可先在事项内本地预览，查看不发送、也不占用模型次数。 双语稿从所选已保存正文明确选择中文或English，点“调用交融并另存语言稿”；仅发送此固定正文（最多4000字符），未保存编辑不发送。完成后点“读取已保存结果”再选新稿，核对编辑／保存，TXT、MD或DOCX均取明确已存版本。原稿和内部版本依据分开保留；同原稿版本和语言已有稿时直接打开，不覆盖人工编辑或重复调用。翻译含义与正式外发由本人核对，其他语言保持待核。

签证休假返岗事项的“各材料的办理声明与回执”：先读取最新记录，选择材料／记录性质，注明本人已保存来源行号和实际说明，再保存。核对回执须明确选择同类已引用回执，程序沿用其固定原处；旧依据、跨类回执不能直接确认。实际日期未知留空；提交声明与回执原文核对不证明真实提交、签发、批准或可通行。暂停期间仍可如实登记，恢复后可另存带历史的可编辑核对稿；原人工稿保留，导出取固定保存版本。

签证休假返岗的“材料日期与个人核对待办”：先在材料清单保存明确日期、准确原处并本人核对，再读取节点，选择材料、等待对象和带UTC偏移的个人提醒时间（未知留空）后建立待办。沿本人等待点编辑／保存，暂停仍可维护，重开保留；恢复后准备私人跟进稿。材料或相关航班／要求变化会保留旧待办并提示重核，阻止沿旧依据准备新文字；核对旧文字和提醒后明确采用当前材料依据。材料日期不等于办理截止、过期判断、正式效力或消息送达。

签证休假返岗事项保存本次授权要求和材料文字后，明确调用模型整理，再点“读取已保存签证休假返岗材料匹配候选”，选择有原处的要求追加到核对清单。所有候选初始待核，缺材料不填已提供；本人核对原文、修改备注并保存，暂停可维护，恢复后另存要求与材料核对准备稿，可编辑保存并下载固定版本。模型自由备注只在独立核对区保留，不选入清单或当日期计算、效力及通行依据；正式名称、适用、原件、提交和回执分别核对。

材料日期面板的“程序日期核对”只读取本人确认的存值：纯年月日比较日历日先后与差值；日期时间须在行程口径中明示共同UTC偏移后才换算比较日期，不截断时间或补默认时区。同日不代表整个当天有效，日期先后不代表证件有效、过期或可通行。休假与离营／返营端点各自显示，未知端点不由另一日期推定；关联行程换版须重核。读取当前结果后可“另存程序日期核对稿”，暂停阻止生成新稿，恢复后可另存、编辑并导出固定版本；旧稿和真实手续状态保留。

`python package.py`只制作本地应用代码包，不发布、部署或上传。包内只有代码和空配置示例，不含运行数据、账号、真实模型配置和测试夹具；应用包与当前工作数据分开保留。

费用／物资事项展开“明细与可靠计算”→“选期／选行汇总与固定导出”，读取已保存明细，明确选期间／逐行选择。原述期间不自动转换月季，不同币种、物品、单位、期间分别计算；同原处完全重复行请排除或本人写明分别累计口径。备注可补已知项目／组织范围，未知留待核。另存汇总后从稿件列表主动选择、编辑保存，历史记录可下载本次固定选行CSV，原全量明细保留；暂停停止新汇总但仍可保存人工稿，刷新后已保存汇总和人工版本续办。未另存的范围选择只保留当前浏览器页，刷新不当已保存；来源／事实换版须重核保存明细，历史CSV不随后续明细编辑变化。不据此判缺报、报销批准、支付、库存余额或真实收发。

出行事项可从已保存原话明确调用交融，然后展开“从原话读取已保存模型出行计划”→读取→选中带出处的候选→填入空白计划草稿。此读取不再调用模型，不覆盖人工值或已核值；字段仍为候选，营地出返含义和实际日期由本人核对后沿“保存计划与明确语义”保存。相对时间／缺年／缺时区保持待核，航班时间不能替代营地出返。暂停仍可人工核计划并保存，刷新保留已存字段；恢复后另存同修订四轨稿，主动选新稿、编辑保存及固定导出。来源或计划换版后旧模型批次待重核，不可直接再次填入；保餐原述不自动创建餐次明细或减餐，计划不登记实际出返、批准或派车。

厨师在“已发布菜单”读取本人菜单自愿反馈后，可查看按原述菜品的本次已读核对摘要：意见条数与提交账号数分别显示，同账号多次意见不充全员人数。逐字相同原话／约束只提示重复组，不删原意见，不把不同文字推断为多数或采纳；本人饮食约束逐条单独保留。沿原意见保存厨师文字回应，员工在本人持续事项读回和明确更正／撤共享。更正后旧回应保留历史，当前范围回应数重新核对；重读后撤共享意见从厨师摘要移除，本人私存保留。摘要只对应已读菜单版本及当前获授权投影；无应报基线，不核未反馈人数，也不证明实际供餐或厨房已保障安全。


厨师读取本人菜单意见后，在“所选意见的模型归纳与回应候选”先“读取选择依据与已保存候选”，明确选择1至8条原话，再调用真实交融。饮食约束默认不发送；只有明确勾选才加入所选意见的约束，未发送不表示无过敏。只发送所选原话、相关菜品及公开菜单日期／餐次／菜品，不自动加入账号身份或私人来源。点击读取查看待办、失败或已保存主题及逐条回应候选，读取不再次调用；同依据已有成功批次复用。候选逐条引用，程序核覆盖不证明语义准确。核对后只填空白回应框，已有人工文字保留；直接编辑并明确保存后才登记厨师本人文字声明，员工可读回、更正或撤共享。原菜单事项暂停／人工接手时不发新模型请求，人工回应仍可保存；刷新／重新登录读回已存候选与回应。更正、撤共享或菜单／原事项依据变化后，旧批次不给继续读取内容或填入，不自动重试；此前已发模型或明确取出的副本无法召回。此界面的未发送选择、发送约束开关及未保存回应仅在本页保留，不将刷新当保存；不改采购、菜单、实际备餐或供餐。


厨师读取当前菜单意见后点“修订公开菜单”，可在“本人明确在这次新版菜单采用的意见”逐条选择（默认不选，最多8条）并写明新版对应做法。公开菜品／备注由厨师直接编辑；私人意见、提交者和饮食约束不会自动复制到公开快照。点“保存并发布修订”后，新版菜单与每条本人采用声明同时保存，采用说明仅给对应员工和厨师查看；普通菜单修订无需采用或回应。员工在本人意见事项“读取独立提交状态”可查看声明与固定新版日期／餐次／菜品／版本，刷新后仍可续办。意见更正或撤共享后不能沿旧选择继续发布；读取当前意见、核对原说明，再重新勾选当前原话，说明及修订文字保留。已有声明在员工再次更正后标历史，不自动移动到其他菜单版本；撤共享后本人历史保留。暂停只停止助理准备，厨师本人明确菜单修订与采用声明仍可保存；声明不证明实际备餐、供餐或安全核验。未发布的选择与说明仍只在本页，刷新不当保存。

出行／签证休假返岗事项展开“所选行程餐次需求汇总与厨师只读副本”→读取本人行程→明确选择1至12份已保存行程及用餐日期→核对去重和冲突→另存汇总。在稿件列表选择新稿、人工编辑保存；暂停可编辑，刷新保留已保存版本，恢复后可继续新准备。以人员原述引用＋日期＋餐别合并，同引用的保餐／调整／待核冲突单列；另日不参加。引用数不是已核真实人数，没有完整应报基线，缺记录不当0，不按出返时间自动扣餐。私人原记录供经办核对。

已保存程序汇总可明确选活跃厨师，核对固定正文并勾选分享范围后保存只读副本；只给日期、餐别、引用计数和范围说明，不带私人目标、人员引用、原备注、来源或个人编辑稿。厨师从“收到的准备材料”读取／复制／下载固定版本，操作仍逐次核当前授权；经办可在原事项分享记录撤回，已取得的副本不能召回。多份行程或关联行程换版后旧汇总保留为历史，须重核另存才能新分享。没有厨师账号仍可私人编辑保存。未另存选择仅在当前页面保留，读取不调用模型，不代表备餐、实际供餐、有效减餐或已通知外部厨房。

费用事项展开“费用明细与可靠计算”→“复用本人行程准备费用”：读取本人行程，明确选择一份，核对已人工确认的计划字段再保存引用。可明确勾选用原用途填入空白费用事由；已有人工值保留，不复制同行或私人备注，不把计划日期作为财务期间或实际出返。保存引用后沿原核对入口重新核对并保存已有费用明细，再选期间／行另存汇总，新稿会保留本次计划出处。暂停仍可人工保存引用和编辑稿，重开保留。行程换版时旧费用稿及副本标历史，禁止沿旧依据生成新汇总或新分享，原固定MD／CSV保留；可解除当前引用，已复制事由、人工稿与引用历史保留。

首页直接输入目标，点击“交给助理”；模型已配置时默认选择交融整理，可切换模板或人工路径。新目标默认由助理根据原话判断主要办理类别，同一次整理生成准备稿与具体缺项，不额外调用。类别和来源设置按需展开，也可从后勤服务、行政办公、费用与物资、人员事务和综合事项分组开始；侧栏可筛选整组或单项。出行安排、用餐安排和用餐意见各自独立，关联须有当前原话依据。旧事项不自动换类或改写。

新自然委托事项可在对话旁展开“办理类别”并修正；暂停时仍可修正、编辑保存成果，重开后恢复。已使用具体业务字段或办理记录时保留原类别，避免混淆真实状态；不知道或多重目标仍保留综合事项待核。模型判断只改变准备范围，候选仍须核对，不产生批准或执行。关联候选及本人标题授权续办用法见下。

独立“用餐安排”保存用餐需求、日期／餐别原述和必要人员引用；“菜单管理”承接厨师菜单，二者分别办理。出行不必填用餐需求，未知饭点或是否留饭列待核。

在综合事项或其他业务明确选择交融整理后，助理可从本事项原话发现关联候选（最多4条）；与同次准备共用调用，不扫描其他人或后台额外调用。界面“助理发现的关联事项”列理由、原话行号及可修改的目标，读取建议不再调用。核对后“另存独立事项”保存新事项和可编辑准备稿，原事实仍待核、原事项及人工稿保留；同候选重复点击复用已有事项。可从原处打开新事项，独立编辑、暂停／恢复及重开。建议可忽略，不按类别固定组合，不自动减餐或安排业务。原依据换版后旧候选与独立稿标历史，新准备暂缓；回原事项核对，或本人明确核对当前副本并勾选后解除当前关联，再独立继续，原话／历史仍保留。未保存的候选目标修改只在本页保留。

事项打开后可在对话区继续说补充或修正，并选择交融整理、本地整理或只保存；模型只在明确发送时调用。成果卡“打开并编辑成果”进入原编辑器，保存为人工新版本；复杂事实与办理操作在下方展开。暂停/人工接手仍可保存补充和人工稿，恢复后按需继续整理。补充原话不直接改已核事实，原目标、旧稿和业务状态保留；未发送文字留当前页面，刷新前需明确保存。

对话区“参考已有事项”默认关闭。可先本机读取最近最多10份本人目标标题并保存标题许可，再明确调用交融；不会发送那些事项的正文、事实或其他人资料。对话旁“助理发现的关联”展开后可核对已有目标、写本人备注并关联，不必重复新建；保存关联不改对方。可打开原事项独立续办，解除关联保留历史，关闭标题许可停止后续引用；旧批次须重核，已发送副本无法召回。未知人员、日期及实际状态分别核对。
