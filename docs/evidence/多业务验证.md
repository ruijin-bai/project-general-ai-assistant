本轮发现并交 Leader 修复后复核的缺陷：

- v1 备份连接仅使用 SQLite 事务上下文，未显式关闭，Windows 下测试目录清理报 `WinError 32`。实现改为 `closing(sqlite3.connect(...))`；两项迁移检查及临时目录清理随后通过。

## 增量复核：持续本地整理、声明凭据、结构明细

同日由 Leader 指派独立复核稳定接口及 `tests/test_operations.py` 原始断言。QA 读取实际 `store.py`、`server.py`、`calculations.py`、`preparation.py` 及受影响展示代码，独立执行 `python -m unittest discover -s tests -p test_operations.py -v`，**6 tests / 7.803s / OK**；未重跑首轮 9 项、模型 18 项或计算 12 项已有证据。

实测覆盖：费用十进制 `0.1+0.2=0.3`；物资按物品/单位/期间分组；明细跨事项来源、缺数、待核单位拒绝且已存行保留；事实/来源变更后计算带原修订且 `stale=true`，重新人工确认才更新计算范围；旧幂等请求不重复写入。声明凭据保留来源/位置/陈述人/本地记录人和输入修订，跨事项来源、未知轨道、非法记录类型、相对日期及缺项拒绝；事实变化后凭据 stale，真实业务状态仍 unknown。持续整理仅用本地模板，每次输入一轮，等待时不循环；暂停与人工接手期间仍可人工修订而不排自动任务，恢复可继续；关闭及 20 次总上限有效。

QA 另在 `tests/test_multidomain.py` 补 2 项关键遗漏，用 `python -m unittest discover -s tests -p test_multidomain.py -k auto_workflow -k stale_calculation -v` 只执行新增用例，**2 tests / 1.144s / OK**：

- 自动委托创建重复幂等请求仅产生一个动作；阻塞运行中的模板后暂停并加来源，释放响应后不发表旧成果，动作 cancelled、暂停保持；即便模型已配置，本次模拟模型请求数仍为 0。
- 计算已 stale 后重新生成新准备稿，计算 input_revision 不刷新，正文明确“以下为原核对范围的计算，须重核后用于下一步”，不将历史合计冒称当前已核结果。

结论：本次增量受验关键风险通过，无新增阻断缺陷。本轮仍只证明单机隔离准备层；不验证多身份权限、真实资料/模型、正式批准与执行或真实业务效果。Leader 已提供隔离浏览器自动委托、人工稿跨重整保留及费用两行操作证据，QA 按本次分工复用，未重复浏览器操作，未将该证据计作 QA 独立 UI 实测。
