# 结构成果与会议行动合同

2026-10-08 / V0.1，下一可开发准备切片，未实现/未验证。依据[PRD](../product/PRD.md)第9.2、10节，F-014–019/020/022/023及AC-029/031–033/034–035/037/042；复用[业务准备合同](业务准备合同.md)。只做本人私有范围内的会议整理、逐项跟进与公文结构成果，不建全企业任务库、不派给他人、不发消息、不新建通用共享ACL。

## 1. 当前基础与交付行为

已核 `preparation.py`：meeting已有meeting_subject/meeting_date/notes_text/participants/location/decisions_text/actions_text/source_ref，但准备稿只是文字分段；document已有document_kind/audience/subject/facts_text/template_ref/disclosure_scope/source_ref，但正文仍是通用底稿。`store.py`已有事实修订、可编辑成果版本及私有owner检查，`server.py`可下载最新TXT；`calculations.py`已校验费用/物资source_id与source_position，并用Decimal按币种/单位/期间精确分组。本文不重建这些能力。

本次应实现“原文字来源→可核结构项→编辑/保存→可取出纪要或公文→同一事项逐项更新进度/明确等待”的路径。支持普通目标独立开始，不把制度/审批/共享库作为前置。没有模型或模型失败时保留原文与人工结构编辑；不能用新增字段数、空模板或一段生成文字声称公文/会议全部能力完成。

仅事项owner能读写本切片结构、进度、来源与下载；经办在自己的私有事项整理别人的原述时属于代录，不让责任人账号自动获得指派或访问权。当前身份共享未实现，这里不以cook/service权限或角色字符串放行其他事项。会议室预订、签发、发送、送达、录用、薪资、付款、出入库仍按真实责任与原渠道分开。

## 2. 最少结构及出处

复用revisions.fields的两个固定元字段：`__meeting={schema_version:1,input_revision,structure_version,items}`、`__document={schema_version:1,input_revision,structure_version,sections}`。不能经普通facts任意写元字段，须专用端点严格验证。更新保留未变事实、`__rows`、`__workflow`等既有元字段，产生新修订；历史不删除。保存时请求input_revision校验原基线，元结构input_revision写事务提交后的新revision，避免刚保存即误标陈旧；refs仍指向原始来源行。首次没有结构时为空且明确未整理，不假造决定或行动。

| 对象 | 可直接实现字段与约束 |
| --- | --- |
| 共同出处 `refs[]` | `{source_id,start_line,end_line}`，行号从1开始、含首尾、按sources.text.splitlines()稳定定位；source_id必须属于当前owner该事项，整数行号在范围内。服务端读回对应原文作为excerpt，客户端/模型不得伪造excerpt。不让“source_ref=某文件”字符串顶替实际已读来源；未读取附件继续明示未读取 |
| 会议结构项 | `{id,kind,text,refs,confirmation,responsible_text,responsible_account_id,deadline_text,deadline}`；id为稳定随机标识，不按数组位置重新生成；kind固定discussion/proposal/decision/dissent/action；text非空；refs至少1个真实原处；confirmation candidate/local_checked，仅表示候选或经办核对原记录 |
| 会议责任 | responsible_text保留原述，未知null；responsible_account_id首切片仅允许null或当前owner ID。提到他人姓名不查户籍、不自动绑定账号、不分派、不称已接受；unknown不默认综合经办 |
| 会议期限 | deadline_text保留原话，未知null；deadline=`{kind:'unknown',value:null}`或`{kind:'date'|'datetime',value:明确ISO值,confirmed:true}`。相对时间、缺年、仅“尽快”均unknown；明确ISO值须来自记录或新增获授权确认来源，不能模型补日期 |
| 公文段落 | `{id,heading,body,refs,confirmation}`；heading可空、body可暂空但标待补，完成成果需要实质正文；id稳定；refs至少1个同事项原处，允许不同段共用同一事实底稿出处；confirmation candidate/local_checked，不代表组织签发 |

会议decision只有在经办核对原记录明确决定时才显示“记录中的明确决定（附依据）”；候选分在“待核决定候选”，proposal始终为提议。kind不能由模型候选直接进入组织批准/真实签发轨；同一原文里分歧与决定并存应分别保存，不以多数消去分歧。没有明确决定时输出“原记录未提供明确决定”，不拿讨论当决定。人工更改分类/正文需新修订，模型不得覆盖local_checked项。

行数/文本限制建议：items/sections各最多100项，每text/body最多10000字符，每项最多10个refs，沿HTTP请求总体128KiB限制；超限返回422可分段保存，不静默截断。删除项须显式removed_ids并保留历史；传入列表缺项不自动删除。结构保存用增量upserts，未知键/重复ID/他事项ID拒绝；confirmation是当前账号校核声明，不伪装实际参与人。

## 3. 私有会议行动与可靠日期

会议action结构项就是本次行动索引，不新建任务表。进度写既有events的`meeting_action_progress`固定JSON：`{item_id,item_revision,command,evidence_class,reported_by?,note,occurred_at?,actor_id}`；actor_id由session产生，事件recorded_by同actor。command固定self_accept/self_start/self_blocked/self_claimed_done/reported_progress/result_note。会话主体只能对负责账号为自己的项记self_*；条目责任仍只是他人姓名或未知时，只能reported_progress/result_note，不能把自己登录当别人的真实承接。

`evidence_class`由程序指定self_statement或transcribed_statement，客户端不能自行改verified；self_claimed_done是本人声明完成，result_note是经办结果核对说明，不把声明、转录或生成稿变成实际验收。负责他人的项允许经办写“某人原述进度”，明确reported_by及note，保留实际陈述人与记录人；不增加每人账号、批准或强制汇报门槛。无真实接受来源显示“承接待核”，无进度显示未知，不自动未开始或已完成。

服务端从结构项及进度事件派生展示：原述责任/期限、候选/已核原记录、本人声明/代录、等待谁、下一步。同一item只在本事项列表出现一次，多条进度不重复统计行动；本人的待做与“等待他人原述反馈”区分。首切片不做定时对外催问；仅打开/读取时计算期限提示，暂停/接手停止未来AI整理，不删动作历史，有权者仍能记录实际已发生进度。

可靠比较：date仅与明确的`as_of_date`按同一已声明显示时区比较，只有value < as_of_date才标“明示期限已过”，当天不标逾期；datetime仅允许带明确UTC偏移的ISO时间，转UTC比较，缺时区拒绝确认或保留unknown。不同精度不混合比较。结果带as_of和时区范围；期限unknown、源待重核或只有代录未核期限时不给逾期结论。提示期限已过也不推任务失败、处罚或已违反制度。

事实/来源修订使原结构input_revision可见需重核；纯进度事件只bump事项行version，不增事实revision或把所有段落无故变stale。结构修改行动正文、责任/期限时递增该item_revision（另在元结构项中保留递增整数，初值1），旧进度留历史并标旧条目范围；不得把旧接受/完成自动套新动作。正文未变、只改其他项时保留未受影响项的item_revision与人工核对。模型重新生成仅形成候选upserts，仍用原revision/control_epoch栅栏。

## 4. 结构成果、导出与接口

结构公文按heading/body顺序确定性渲染Markdown；会议纪要按discussion/proposal/decision/dissent/action分组，含实际来源位置及候选/待核标记，行动显示原述责任、明示期限、独立进度。渲染给现有artifacts新成果（type=document_structured或meeting_minutes），固定input_revision，不覆盖已人工保存稿。用户也可直接编辑成果正文并保存新版本；正文编辑不自动改结构/真实决定/行动轨，两者不一致时明确“正文有独立人工修改”，由用户选择取出哪一成果。

TXT和MD为本次真实可取出格式。下载固定artifact_id与指定version，UTF-8字节、相应Content-Type、Content-Disposition、安全文件名（不得使用用户标题形成路径）。取出稿保留“通用准备稿/本地核对范围/待核”说明，不加盖章、正式文号、虚构署名或版式合规声明。接口返回下载成功只表示响应已提供，不称外部发送/送达；页面复制和浏览器实际下载的活动与业务状态独立。

不增加DOCX依赖作为此次交付门槛。以后选DOCX须明确通用排版与未核正式模板边界，生成真实文件，实测可打开并渲染检查段落/分页/表格/文字溢出后才称可用，不能仅换扩展名或把TXT响应当DOCX。

| 接口 | 固定调用约定 |
| --- | --- |
| `POST /api/matters/{id}/meeting/structure` | owner、meeting；`{expected_version,input_revision,base_structure_version,upserts,removed_ids}`；验证同事项refs/白名单/稳定ID，事务新修订；返回结构、revision/version及待核，不代组织确认会议 |
| `POST /api/matters/{id}/document/structure` | owner、document；同上请求，upserts为sections；不要求模板、审批、共享库。只保存非空段落所用事实与可编辑正文，待补段可保存但不称完整文稿 |
| `POST /api/matters/{id}/meeting/actions/{item_id}/progress` | owner；`{expected_version,item_revision,command,reported_by?,note,occurred_at?}`；校验本人/代录与当前项范围，新增事件；旧条目或陈旧版本409，返回独立进度与等待 |
| `POST /api/matters/{id}/structure/render` | owner，document/meeting；`{expected_version,input_revision,structure_version}`；准备未暂停时生成新的结构成果候选，必须有实质内容；暂停时409可继续编辑/下载已有稿。旧revision/control_epoch不发布，返回artifact_id/version，不改正式轨 |
| `GET /api/artifacts/{artifact_id}/download?version=N&format=txt\|md` | owner当前来源权限再次核对；只取固定存在版本，不静默降为最新；无权404、非法format/version422。下载UTF-8真实正文；单凭下载请求不宣称浏览器已保存或接收者已收到 |

写请求沿session CSRF、幂等键、expected_version；跨账号、直接ID、历史下载、幂等回放先核owner，不扩大共享。接口缺结构/来源时返回具体阻断项并保留人工输入。以上源定位、结构与导出为新增合同，不把现有自由文字页面称已实现。

费用/物资继续用现有`__rows`及`rows/confirm`合同，不重算或清空历史明细；Decimal按确认币种/单位/期间分组、缺数不当0，结构保存不得破坏它们。人事只准备授权材料/要求核对，录用/签发/薪资/处罚由真实责任人，未知仍待核；此次不增加人事正式动作。

## 5. 最少验收（四组，尚未执行）

1. **会议结构与出处**：同一来源含讨论、提议、明确决定、分歧、无期限行动；分别形成稳定项和真实行号excerpt。缺年/“尽快”保留原文unknown，不造责任/决定；新来源/修订后需重核、人工项不被模型覆盖。保存后重开同事项可编辑，不重建新会或外派行动。
2. **行动独立与日期**：本人声明与代录分别读回；他人姓名项不能self_accept/代称其本人完成。明确日期/时区才按程序比较，当天/过期/未知/缺时区/旧item_revision各有正确结果；改责任/期限后旧进度留历史，不变其他项。暂停仍能录真实进度、AI未来渲染受栅栏。
3. **公文及真实文件**：编辑两段有底稿出处的实质正文、保存/渲染、再改人工正文并取固定版本TXT/MD。HTTP下载字节保存为隔离实际文件，UTF-8重读与对应artifact正文一致；中文、换行、标题/段落可读。无模板明示通用稿，无签发文号不补造，不称正式送达/版式通过。
4. **隔离与保全回归**：另一账号直接结构/进度/历史下载/幂等回放无权；旧版本冲突保留输入。新结构保存不清`__rows`/已确认事实/来源/人工成果；原费用物资精确汇总维持同输入同结果，重启读回新元结构和事件；本次无外发/录用/付款/收发变化。

本合同只完成下一切片设计。完整公文、会议、多方协作、人事及全部PRD仍按实际行为继续开发与验收，不能因模板/结构字段已注册判最终目标达成。
