# 本地独立身份与菜单反馈合同

2026-10-08 / V0.1，下一开发切片设计，尚未实现或验收。基线：[PRD](../product/PRD.md)第3、8、10节，F-003/009/014/016、AC-006–007/022–023/028–029/035/039；[业务准备合同](业务准备合同.md)第1、3节；[架构方案](架构方案.md)第3、10节。用户授权持续开发，范围仍为隔离本地竞赛版本，不接现场身份/生产权限、不批准派遣扣餐。

## 1. 本次切片与现状

本次实现：独立账号登录；employee 自有私有事项；clerk 仅获明确共享的准备范围；cook 对本人菜单显式发布/撤回；employee 对已发布菜单自愿反馈；反馈归本人且仅向对应厨师提交。executor 只冻结必要服务投影合同，报修/清洁分派与执行者真实承接不混入本次菜单切片完成标准。

当前核实 `server.py` 的 `/api/session` 无登录且返回进程全局 CSRF，`store.py` 使用全局 `OWNER=local-preview`，Runner 同样通过这个隐含主体读写。仅增加登录页面不能完成隔离；请求、Store、下载、幂等回放和后台任务必须一起改为显式账号/授权。

本地账号代表独立登录主体，操作日志不可将 clerk 写成 cook/employee。账号与实际人的对应由获授权管理员核对，隔离测试账号须标明工程身份。密码登录证明当前凭据持有者，不能证明法定实名，亦不抵御掌控本机/数据库的管理员。系统不提供切角色假账号、代登录、`actor_id` 请求参数或把口头陈述当本人账号操作的入口。正式人员对应与生产权限仍待Q-010；未核默认私有/无权。

## 2. 账号与首次引导

采用标准库密码哈希和内存会话，不增认证服务、第三方依赖或JWT。明确选用 `hashlib.pbkdf2_hmac('sha256',...)`，每账号随机至少16字节盐，初始600000轮；哈希算法/轮次随账号保存，登录恒时比较。实现需实测目标机器登录耗时与并发上限，不把本次参数称生产安全认证。密码仅经JSON或本机交互输入，最多256字符、至少12字符，不静默截断；密码/原token不进入事件、模型、URL、控制台证据或Git。登录对不存在账号使用同成本虚拟哈希，错误统一“账号或密码不正确”。

首次创建管理员采用**本机CLI交互**：服务未启动时、持有应用数据目录文件锁的管理命令，仅在 accounts 没有不可删除的 `bootstrap_admin` 标记账号时可用，用户名明确输入、密码用 getpass 两次输入。引导事务建立该账号及标记（唯一部分索引约束只允许一个）；成功后入口永久关闭，该账号停用也不重开引导。恢复管理员只通过明确本机维护命令＋备份＋审计，不由浏览器自动抢占；不是自动完成所有管理员恢复操作的授权。

管理员只管理本工作区账号、启用/停用、职责授权和本地引导，不隐含任何事项、来源、菜单发布或批准权限。不开放公开注册/用户选择特权。管理员创建待激活账号时指定唯一用户名、显示名及已核职责（employee/clerk/cook/executor 可真实兼任，admin 单独标记）；系统产生一次性激活token，存摘要、到期时间和待激活状态。token 只在本机管理界面一次显示，由实际管理员按原渠道交给实际本人；本应用不自动发消息。本人用token 设置自己的密码，原子消费token并激活；重复、过期、已消费均拒绝。管理员不能通过API读取密码或直接指定他人密码，重置仅使账号重新待激活且撤销原会话，明确记录执行管理员与时间。

token 流程仍依赖实际交付和本人核对，不能据一次激活称已验证真实实名。管理员授权 cook 是实名对应/职责核对的本地信任点；不允许客户端角色切换或 clerk 临时“以厨师身份”发布。职责变化记录前后范围和管理员，服务端每请求读现授权；管理员管理权限不作为安全、厨师等业务职责。

## 3. 会话、CSRF与退出

服务仅绑定127.0.0.1，统一使用一个 canonical origin（例如 http://127.0.0.1:8765）；localhost 可引导到 canonical，不能接受跨主机宽松同站逻辑。保留Host/Origin/Sec-Fetch校验。页面资源和health可匿名；业务API和模型状态需登录。

采用不可预测32字节会话token，cookie `assistant_session` 设 HttpOnly、SameSite=Strict、Path=/，不设置Domain。当前loopback HTTP不用Secure，故不能宣称支持远程生产部署；未来HTTPS部署必须另外核定。服务只存token摘要，对应账号ID、账号auth_epoch、会话随机CSRF、创建/上次活动/失效时间，内存加锁管理。绝对期限12小时、空闲期限30分钟为本地切片初值，可配置；重启清空会话，账号与事项保持。账号停用、重置密码/职责变更递增auth_epoch，立即令所有既有会话失效。

`GET /api/session` 未登录返回 `{authenticated:false, csrf_token, mode:'isolated_local'}` 并创建短期匿名会话；登录、激活、退出也校验该会话CSRF与同源。登录成功/权限改变/退出均轮换或销毁token，不能沿用匿名会话ID。登录后返回当前主体显示名、服务端职责、登录态及本会话CSRF；不得返回密码哈希、其他账号或原token。写请求需当前会话cookie＋对应CSRF，不再用进程全局token。

限制单IP/账号尝试速率与并发哈希数，初值每账号或本机每分钟最多5次失败，短时429，不做永久锁死；管理员引导及激活同样限流。限制值只作工程初始参数，需定向测试共享本机浏览器不会串会话。会话退出后前端立即清空事实、来源、成果、剪贴板候选、草稿内存和列表；异步响应通过当前会话/选择epoch拒绝回写。未经保存的私人草稿不在其他账号展示。浏览器同一cookie容器切账号会使共享标签页转入新的主体，服务端必须每请求核身份，前端不可假定旧身份；测试用独立cookie jar/浏览器上下文。

## 4. 最少持久结构与授权

在v2六类业务记录之外只新增三类必要小记录；会话不建表，反馈复用 matters/sources/events/artifacts。

| 结构 | 固定字段/约束与用途 |
| --- | --- |
| `accounts` | `id` 随机ID；`username_key` 规范化唯一；`display_name`；`password_hash/salt/kdf_iterations`（激活前空）；`state` pending/active/disabled；`capabilities` 固定白名单JSON；`is_admin/bootstrap_admin`；`auth_epoch`；`activation_digest/expires_at`；`created_at/created_by`。账号硬删除不在本次范围，停用保留真实日志；保留禁用、不可登录的legacy标记账号 |
| `matter_grants` | `id,matter_id,artifact_id,artifact_version,account_id,scope,dependency_refs,granted_by,version,revoked_at,created_at`；成果固定版本/账号/scope唯一；scope 初次仅 `read_preparation`（后续 `assist_preparation`、`service_projection`/`service_response`）。dependency_refs为固定来源ID/授权版本数组；只读scope仅授权该成果安全快照，不授权matter详情、facts、sources或全历史。撤回不删除历史；账号职责不是全库访问权 |
| `menu_publications` | `id,source_matter_id,source_revision,publisher_id,menu_date,meal_slot,dishes,notes,version,status,published_at,withdrawn_at`；status published/withdrawn；每次发布固定快照，新修订建新publication或明确版本，不修改已提交意见的归属。日期/餐别/菜品/备注为显式安全发布字段，不存整个准备成果 |

原 `matters.owner` 保存真实账号ID；sources.recorded_by/events.recorded_by/revisions.confirmed_by 用当前账号ID，`reported_by` 只保留陈述人原话，不能改变实际操作者。actions 增 `actor_id/auth_epoch/access_snapshot` 或等价固定结构列，artifacts增固定格式 `dependency_refs`（来源ID/授权版本与字段范围）；模型输入来源ID/权限依赖在快照，停止/权限栅栏跟随动作。幂等身份须纳入fingerprint及回放授权：同键既往响应不得泄漏给另一账号，任何回放先鉴权。继续保留已有全局唯一键也可，但别名主体必须冲突或404，不能返回他人响应。

私有事项owner默认能读写自己的准备内容、事实与来源；共享由owner显式授给当前活跃clerk。`read_preparation` 只读本次准备事项及已选择的来源/成果；若不能精确字段投影，切片只共享明确选择的单独准备成果，拒绝共享整份敏感事项。`assist_preparation` 额外允许准备、保存独立成果、补来源/确认本次已授权事实；不允许改owner、再分享、读未选来源、替本人确认、菜谱发布或任何正式批准。未知scope拒绝，不允许客户端提交任意字段权限。

**最小可实现收敛**：本次允许完整私有事项owner操作；clerk共享先仅 `read_preparation` 的独立安全成果快照，暂不赋协作写入，界面明确“未开放代理修改”。这样不用为每业务先建通用字段ACL；下一次扩写再冻列投影，不能以read scope获得写权限。服务端权限检查支持 `can(actor, operation, object)`，结果唯一、默认拒绝；不要散落按角色字符串直接放行。

executor 合同保留：仅获具体分派的 `service_projection`，读取单独固定服务字段（repair:地点/问题/可进入时段/必要联系；cleaning:地点/范围/时段/已核进入许可/必要联系），无来源、私人材料、完整成果、其他执行者任务；`service_response` 只能记录本人承接/障碍/处理声明，不能闭单/重分派或覆盖经办事实。本切片不实现时所有executor服务操作403，不能显示已支持真实闭环。

## 5. 菜单发布、撤回与自愿反馈

菜单准备仍是owner私有事项；cook须对自己menu事项的当前事实修订显式提交发布，服务端验证账号cook职责、owner、`expected_version/revision`、明确ISO日期/餐别/非空菜品。clerk即使获共享或admin权限也不能发布/修改/撤回该cook菜单。职责真实兼任时按该账号已核cook能力操作，日志仍是本人，不伪装另一个厨师。

发布请求只接受 `menu_date,meal_slot,dishes,notes` 四项公开给本工作区活跃employee的内容，明确提示发布范围。备注由厨师明确编辑并确认，默认空；不自动带入员工实名、私有忌口/过敏、电话、来源原话、模型活动、模板完整稿或账号清单。模型不能触发publish；AI候选要厨师明确采用。发布是本地独立账号对隔离工作区的软件操作，不声称现场微信群发布/实供/库存变动。

员工看列表和publication详情，仅返回发布快照及厨师显示名、时间、版本、状态；不接受publication→matter/source/artifact私有入口。撤回由原publisher当前有效cook身份或已明确授权的停用处理机制执行；切片先仅publisher可撤，管理员可停用账号但不能冒充撤菜。停用publisher使其菜单暂不对员工提供，页面显示“发布者已停用，内容待核”；管理员只能管理可见性/账号，不记录厨师撤回。撤回或停用立即禁止员工读取原公开正文/下载/对新版本提交反馈；保留历史给原publisher/本人反馈的有权者。已下载副本无法召回，禁止作相反承诺。

员工自愿反馈接口 `POST /api/menu-publications/{id}/feedback` 接受明确所看publication版本、非空意见及可选菜品、明确约束，不要求每日评价/理由/批准。服务端创建domain=feedback的私有事项，owner=当前employee、menu_ref=publicationID/版本、来源实际操作者=该employee；用户不能提交其他account_id/reported_by冒充他人。提交动作明确“提交给本菜单厨师”，形成只给原publisher的反馈安全投影，不能默认全员看意见，clerk/admin无默认查看权。

反馈普通保存/提交不调用模型、不等待厨师审核。本人可改自己的意见（新修订保留原文）、撤回共享；厨师只读本菜单实际提交投影，可记录本人回应，不能改员工原文。汇总按当前可见真实feedback事项ID/actorID归组，明确日期、餐别、版本与范围；重复请求按幂等处理，同一人多条不伪装多个人，多个匿名代录来源不能归为真实账号人数。保留少数/分歧/明确过敏，意见不改菜单、采购或库存；未回应不阻软件反馈任务结束。菜单修订不自动将旧版反馈移为新版反馈。

## 6. 接口、撤权与派生成果

新增候选接口（具体命名由Leader冻结，调用约定不可省略）：

- `POST /api/auth/login`：username/password，匿名会话CSRF；成功轮换cookie；401统一凭据错误、429限流。`POST /api/auth/logout` 销毁会话；`POST /api/auth/activate` 一次性token/password，消费后需独立登录。
- `POST /api/admin/accounts`、`POST /api/admin/accounts/{id}/control`：仅admin；建立待激活身份/明确职责、停用或重置，expected_version或auth_epoch校验；管理响应不包含密码和其他业务内容。
- 原事项/来源/成果/工作列表/下载API：全部要求登录，传actor进入Store；对象不存在或无读取权限统一404，已可读但动作无权403；匿名401。客户端不以隐藏按钮替代权限。
- `POST /api/matters/{id}/share` 与revoke：仅owner，指定活跃clerk及独立安全成果快照，expected_version、幂等；共享源换版不自动放宽范围。
- `POST /api/matters/{id}/menu/publish`：当前owner cook，版本/修订及四公开字段；返回固定publication。`POST /api/menu-publications/{id}/withdraw`：publisher，expected_version。`GET /api/menu-publications`/详情：活跃employee读当前发布投影。
- `POST /api/menu-publications/{id}/feedback`：employee，所看version、意见；返回本人反馈事项与来源；publisher反馈汇总单独投影读取，不返回其完整私有事项。

来源/共享撤回时，在一个事务内撤grant、递增事项access版本或控制epoch、取消受影响pending动作，权限依赖落在派生成果。后续任何详情、旧artifact ID、下载、共享历史、列表计数、事件、缓存、幂等回放、模型/汇总都重新查权，不能读取权限已撤的来源/派生内容。已保存人工稿保留在有权owner的历史，不因撤权删除；曾有权第三人不能经旧共享快照继续读。源owner不可在撤回后由其他人继续自动模型准备，后台写回再校验actor活跃/auth_epoch/grant版本及所有来源权限，失配cancelled并保留已有合法记录。

默认不允许跨事项自动引用他人私有来源；发布菜单用单独明确四字段，是显式披露操作，不自动把原来源权限授给读者。派生成果安全字段未核时拒绝共享/导出给第三人；当前账号自有导出仍逐次查来源权限。模型不能决策“这段已经摘要可公开”。

## 7. v2兼容、备份与验证

版本迁移由Leader独占串行实现：v2→v3先SQLite backup API一致快照，记录备份路径与schema；停Runner/无其他写入，事务新增必要账号/授权/发布表及动作/成果依赖字段，引用检查通过才user_version=3。不清库、不重建全部六表；失败回滚并保留v2文件和备份。既有local-preview用一个保留相同ID、disabled且无任何职责/密码/bootstrap标记的legacy账号承接历史引用；事项不自动归新admin或任意employee。管理员完成引导后经明确“认领旧本地准备记录”操作指定活跃clerk账户，只变事项当前owner，并在事件中保留legacy owner与实际认领操作者。认领前不能通过默认全局OWNER登录读取；认领不是把旧声明追认为真实账号操作。迁移不得改人工成果内容、ID、事实修订或既往reported_by/recorded_by。

旧queued/running动作迁移时设cancelled待用户核对，不以新账号自动执行；新动作带actor/授权快照。新安装仅创建schema与未引导标记，不预置共享密码或特权演示账号。备份含账号hash须按本机私有数据处理，不能提交Git/证据附件；恢复后全部内存会话失效，再登录、查account/grant与未决动作，不能恢复旧浏览器token。

最少验证（隔离账号夹具，未执行）：

1. admin-only引导不能重复；用户提交cook/admin字段不能自提权；activation token只能消费一次；错密、过期、退出与账号停用后读写401。
2. 两employee私有事项在worklist、直接ID、source/artifact下载、旧版与幂等回放均隔离；admin/clerk身份不自动读全库；撤共享后旧入口/派生/缓存失效。
3. cook发布自己的明确快照成功，employee能查看；clerk/admin/另一cook直接发相同请求403/404；发布输入没有电话、个人过敏来源/原话泄漏。菜单发布不改变备餐/实供。
4. employee一次自愿意见直接提交，本人可改，原cook只看显式提交的反馈投影；其他employee/clerk无权；伪actor拒绝；重复幂等请求一条反馈。同人多条、少数/分歧/过敏不扭曲人数或约束。
5. 菜单撤回后旧URL、下载、新反馈不提供正文或允许提交；保留owner历史与本人反馈，旧意见不移入新版。publisher停用与厨师主动撤回区别显示。
