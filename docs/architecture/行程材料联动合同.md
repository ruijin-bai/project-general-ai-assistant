# 行程、餐次需求与休假材料联动合同

2026-10-08 / V0.1，T-022下一准备切片设计，未实现/未验证。基线：[PRD](../product/PRD.md)第6、9.1节（休假返岗实际在9.1节）、F-004–007/010、AC-001–003/008–009/012–019/024–025；复用当前 `preparation.py` 的travel/leave字段及 `store.py` 的修订、来源、成果、声明事件与owner隔离。此次不查新外部依据，不新增饭点、审批、卡或证明适用规则。

## 1. 可操作切片与最少数据

在本人私有travel/leave事项中，核对计划离返营→人工选定餐次需求→登记实际出返声明/材料来源→同修订取出四轨准备及材料清单。可开始和保存待核，不因现场口径不足停止其他准备。不接真实审批、调度、食堂、NIS网站或外部消息，不生成证明/卡/二维码，不把准备任务完成写业务办结。

继续用六类记录，不增旅程总库。现有facts中的destination/departure_at/return_at/participants/purpose/meal_request和leave_start/leave_end/person/flight_info等保留原值与修订；新增严格元字段：

- `__journey={schema_version:1,input_revision,plan_semantics,meal_requests,travel_link}`。plan_semantics记录离营/返营含义与明确时间口径，不能用flight_info替代营地出返。meal_requests为人工需求明细，不是扣餐计算；travel_link可null或`{matter_id,revision_no}`，只可同owner的travel事项。元字段仅专用端点写，保留其他__rows/__workflow/结构成果元字段。
- `__materials={schema_version:1,input_revision,items}`。固定kind为passport/visa/domestic_proof/nis_entry/nis_exit；每种最多一条当前材料记录，可保留历史修订，不为全体员工建证照库。
- `journey_movement`写events固定JSON，真实计划facts不受其覆盖。四轨准备读同一committed_revision，artifacts保存input_revision和固定准备段；旧准备稿/人工稿留历史。

元字段保存时请求input_revision校验当前基线，记录input_revision为事务提交后的新revision，避免刚保存即标陈旧。纯实际声明事件只增事项version，不改计划revision。原来源新添/计划变化继续沿现有revision/control_epoch使旧后台结果失效，不重放正式动作。

## 2. 明确计划与程序边界

计划最少需要已核目的地、参与人员原述、用途、离营/返营值及语义；未知可保存待核，不假造同行授权。新计划UI允许明确ISO日期或带UTC偏移的ISO日期时间，并保留原话。`plan_semantics={departure_kind:'camp_departure',return_kind:'camp_return',comparison_offset:null|'+HH:MM'|'-HH:MM'}`；comparison_offset是用户明确选定的日期显示/比较口径，不能由服务器时区或目的地推定。航班时间另保留flight_info原述。

| 程序可以确定 | 必须未知/待核 |
| --- | --- |
| 两个带偏移datetime转UTC比较，return < departure拒绝422 time_conflict；明确ISO日期且同日期口径时结束日期早于开始拒绝；leave_start/end日期倒置拒绝 | 无偏移datetime、相对日期、缺年、离营/起飞含义不明不能判可靠瞬时时段；新UI保留原话待核或要求明确，不用默认时区确认 |
| date/date可确认日期范围，但仍缺具体时间；date/datetime混精度只在明确同一日期口径且返营当地日期早于离营日期时证明倒置并拒绝 | 混精度未证明倒置不等于证明时段有效；带/不带时区不能混比，不能派车或推出哪一餐不在营 |
| 同一事项对相同明确人员引用/日期/餐别需求检测重复，返回422提示保留一条；不同offset的datetime按UTC顺序处理 | 不从多个行程条数推出减餐人数；无应报基线不报总人数/缺报/人数0，未知人员不冒充账号或全员 |

旧数据库的无时区计划值原样保留、显示“旧本地口径/时区待核”，不能迁移时补时区或当正式可用。同日或等时不自行规定最短行程时长；缺少正式资源规则只能列候选。新的可靠校验不得放宽已经能证明倒置的旧检查。

餐次需求行固定`{id,person_ref,meal_date,meal_slot,request,note}`：person_ref是本次已核必要人员原述/本地引用；meal_date明确ISO日期；meal_slot由本人明确选择餐别标签（可早餐/午餐/晚餐或自定义）；request为keep/request_reduce/pending，分别“希望保餐/申请调整需求/待核”，不是正式生效状态；note可空。最多100行、稳定ID、增量upserts/显式removed_ids，缺行不自动删除。未知人员/日期/餐别留meal_request原文待核，不进可核明细。

现场饭点、触发、截止、应报基线均未核时，只准备这些人工需求；三餐标签不是现场实际饭点规则，不判预计不在营、不扣餐、不宣称备餐/实供。手工keep不得被重新生成覆盖。取消/改期只将本事项需求列待重核，不写已恢复餐次/已释放车辆；既往实际声明保留。

## 3. 实际出返与材料独立记录

`journey_movement`事件payload：`{person_ref,kind:'departed'|'returned'|'not_travelled',occurred_at:null|带偏移ISOdatetime,evidence_class:'self_statement'|'transcribed_statement',reported_by?,source_id?,source_position?,related_departure_event_id?,note,input_revision}`。actor/recorded_by由session指定；本人声明person_ref为当前账号，代录须明确本次人员原述与实际陈述人，不能用同行参与自动确认他人。来源引用有ID/位置且属于该事项。发生时间不明可null并保留真实原话，记录时间另记；不拿计划填实际。返回声明可明确引用该事项同人员出发事件，只有此配对的两实际明确时点能证明返回早于出发时才拒绝矛盾并保留原输入；未配对/人员不同不自动混比，不补造安全批准。缺批准却已出行可如实登记并列安全待处置。

UI同时显示计划与各实际声明，不把一条转述当已核真实反馈。更正实际声明必须新事件含supersedes_event_id/原因，原事件不删；旧修订回执只保留历史，不自动适用当前新计划。准备层四轨safety/vehicle/movement/meal的正式状态仍unknown，movement另显示已登记何种声明，避免声明轨冒充现场核验轨。

材料最少行：`{id,kind,availability:'missing'|'source_provided',provider_class:'current_actor_statement'|'transcribed_statement',provider_name?,source_id?,source_position?,label?,valid_until:null|ISO日期,check:'pending'|'local_source_checked',note?}`。missing时source为空并显示未提供；source_provided必须真实同事项来源ID/位置，local_source_checked只代表当前经办核对所给来源，不代表签发真实性、外部回执已核或适用条件满足。本人材料由当前账号明确声明提供；经办收到他人材料为transcribed且署提供者，不伪装本人。

元记录仅存材料名称/必要有效日期与来源指针，不复制完整护照号、扫描件、出生信息或无关身份字段；原获授权来源留在私有sources，当前未读附件不称已识别。国内证明正式名称/签发/适用/原件、护照签证要求、入出境卡适用/窗口继续Q-009待核；有效日期已过只能提示该明示日期已过，不能推出签证无效/不许通行。外部提交/收到回执的原述复用business_evidence候选，不改上述本地核对为官方已办妥。

leave可直接用本事项计划字段形成四轨准备；可选travel_link引用同owner已有travel修订，不复制另一套计划。绑定时若已有leave出返值不同须409 link_conflict由owner明确选权威计划后再绑定，旧值留历史；绑定后计划只从链接读，编辑应回原travel，禁止两处静默写。目标事项撤权/不存在404；travel新修订使link标待重核，不自动追最新、改材料适用或删除原清单。多人同行不能批量声称办卡。

## 4. 可冻结端点与四组验收

所有写请求沿owner/session CSRF/Idempotency-Key/expected_version；同键回放先核当前owner，无权404、陈旧基线409，拒绝模型调用写正式结果。字段/值错误422可修，不丢人工输入。首切片render用确定性模板，不因材料引用自动发敏感原件给模型。

| method / 端点 | 请求与结果 |
| --- | --- |
| `POST /api/matters/{id}/journey/plan` | travel/leave owner；`{expected_version,input_revision,field_changes,plan_semantics}`；校验明确语义/时间，事务保存同修订事实及__journey；不足可保存待核但不标可靠时段；返回四轨准备的共同revision与缺项 |
| `POST /api/matters/{id}/journey/meal-requests` | `{expected_version,input_revision,upserts,removed_ids}`；仅需求行，保留人工例外；返回本事项请求明细与rule_status:'unconfirmed'，无扣餐人数/实供 |
| `POST /api/matters/{id}/journey/movement` | `{expected_version,person_ref?,kind,occurred_at?,reported_by?,source_id?,source_position?,related_departure_event_id?,note,supersedes_event_id?}`；本人模式person_ref由session取，代录模式须明确人员；evidence_class由当前账号/明确代录路径确定；事件返回独立计划/实际声明，不批准 |
| `POST /api/matters/{id}/leave/materials` | leave owner；`{expected_version,input_revision,upserts,removed_ids}`；严格材料schema/来源归属，返回逐材料缺项、来源核对、适用/回执待核；不办理证明或卡 |
| `POST /api/matters/{id}/leave/travel-link` | `{expected_version,travel_matter_id,travel_revision}`或明确unlink；核同owner/plan冲突；返回固定引用或待核，旧链接留历史 |
| `POST /api/matters/{id}/journey/render` | `{expected_version,input_revision}`；非暂停，生成同revision安全准备/用车需求/计划与实际声明/餐次人工需求四段，leave另附材料清单；返回可编辑artifact_id/version。现有固定版本TXT/MD下载复用；不改formal轨 |

最少工程验收（隔离夹具，未执行）：

1. **时间语义**：跨offset实际顺序、明确日期倒置、混精度/缺时区/相对原话分别读回；可证明倒置拒绝，不足保待核，航班时间不改计划离营。旧值/人工稿保留，同revision四轨成果一致。
2. **餐次需求**：人工keep/request_reduce保存、重复同人同餐拒绝；无饭点/基线只返回需求与待核，无扣餐/总人数/实供。改期或取消标待重核，手工keep与既往声明不被生成覆盖。
3. **材料/关联**：缺国内证明、入境/离境卡分别显示未提供；同事项真实来源指针可人工核对但不称已办妥。其他账号链接/来源404，冲突链接409；travel改期旧清单待重核、引用/人工历史仍在，不造证明/卡/通行结论。
4. **声明/恢复**：计划不填实际；本人/代录、时间未知、迟到更正分别保存，缺安全批准实际出行声明仍可记且不补批准。暂停后未来render停止但可记实际声明；重复请求无双事件，旧revision/后台结果不覆盖新计划；重开恢复元数据与人工成果。

准备可用与旅程/手续办结分别显示；Q未核仅阻相应正式业务结论，不阻本地材料准备与持续修正。此次切片不表示整个出行餐次/休假PRD或最终目标完成。
