# 项目综合AI助理

面向项目部综合管理部的全新 AI 助理，帮助员工和综合部经办人整理需求、核对条件、准备成果和跟进实际工作，减少重复填写、转达与追问。正式品牌未定。

本地工作区 v0.3 已可运行：一句话委托、补充后持续本地整理、业务准备、可编辑成果及人工稿保护、保存续办与暂停接手。报销和物资明细由程序精确核算；声明/凭据候选单独追源，不冒称真实批准或执行。交融客户端已接通，已有真实工程调用记录；独立账号已有本地工程验证，外部业务渠道仍未接入。完整目标持续推进，不以优先里程碑或模板数量判完成。先读 [工作规则](AGENTS.md)、[当前状态](docs/CURRENT.md) 和 [任务清单](docs/product/任务清单.md)。

代码仓库：[ruijin-bai/project-general-ai-assistant](https://github.com/ruijin-bai/project-general-ai-assistant)（公开）。仓库保存源码、测试及项目文档；真实模型配置、运行数据库、账号数据和本地历史应用包留在本机，不随代码上传。新克隆默认没有模型凭据或已有运行数据，按下文配置并启动。

设计依据见 [PRD](docs/product/PRD.md)、[UX 方案](docs/design/UX方案.md) 和 [架构方案](docs/architecture/架构方案.md)。竞赛阶段优先轻量数据和简单启动。

运行需要 Python 3.11+，没有第三方应用依赖。在本项目目录执行：

```powershell
python -X utf8 run.py
```

打开 http://127.0.0.1:8765。也可运行 `./start.ps1`；使用 `--port` 指定其他端口，使用 `--data-dir` 指定本地数据目录。按 Ctrl+C 停止。默认数据在 `.runtime/`，页面关闭不会删除已保存事项，同一数据目录仅允许一个实例。

v0.3本地独立账号模式、菜单意见、服务承接及会议/公文结构已通过对应独立工程检查。要体验独立账号、厨师发布与员工自愿反馈，先停止同一数据目录的服务，在本机交互终端执行：

```powershell
python -X utf8 run.py --setup-admin your-admin-name
python -X utf8 run.py --multi-user
```

首次引导仅终端交互输入密码，不提供默认共享账号；建立后永久关闭。管理员登录后创建已核职责的待激活账号，激活码仅一次显示，实际本人自行设置密码；应用不发送激活码。管理员没有隐含业务权限。旧预览数据升级前一致备份、保留原人工稿与操作者，管理员明确选择已激活综合经办认领后由该账号续办。schema3目录即使漏写`--multi-user`也要求登录；私人事项只本人读取，菜单仅明确四字段快照，实际备餐/供餐仍另核。仅绑定127.0.0.1，不将本地账号称生产实名认证或远程部署完成。

模型未配置时提供规则/人工准备稿，输入和正式业务状态分开，不将模板整理称为AI生成。配置参考 [.env.example](.env.example)，由使用者在项目`.env`填写已许可凭据并显式启用；启动只读取此指定文件，也可用`--model-env`指定，不搜索其他目录或打印密钥。固定交融路线和模型见示例；网页选择模型整理并点击才发送本事项目标/必要事实/来源文字，不自动发送人工稿，不外部回退或重试。配置就绪不代表真实模型通过，实际输出须人工核对。每进程最多30次显式模型请求，实际返回用量保存在事项活动，未返回用量保持未知。

新目标可开启“补充后持续本地整理”，每次新事实、来源或核对明细推进一轮；无新信息时等待、暂停/接手停止，每事项最多20轮后人工继续。费用/物资在明细区确认数值、币种或单位、期间与本事项来源后分别合计；未知数值不当0，事实/来源修订后保留原行与历史计算并标重核。微信文字、口头反馈和在线表选段仍只作人工提供来源，不自动读取或回写。声明转录不认证原人、不核原件，不推进批准/执行。

需求以 PRD 和用户后续决定为准。后续会话先读当前状态和任务清单，不据早期规划止点阻止已授权的开发。

会议和公文可从本人提供的原文行号整理结构项/段落，编辑保存、另存新成果；行动本人声明与代录分别记录，取出明确已保存版本的TXT/MD。无原文决定不补造，未核正式模板保持通用稿。停止同一数据目录服务后执行 `python -X utf8 run.py --backup` 可生成一致备份；`--data-dir`可指定本项目数据目录，备份不迁移原库，不删除原数据。

工程验证见 [v0.2证据](docs/evidence/多业务验证.md)及[v0.1保留记录](docs/evidence/工程验证.md)。schema v1→v2升级前自动一致备份至数据目录`backups`，事务迁移保留六表和人工历史，失败回滚。程序不删除业务数据。复查某个受影响测试时用`python -X utf8 -m unittest discover -s tests -p test_operations.py -v`等相应文件；无变更不重复全部测试。真实模型、正式多人权限、业务效果与目标部署环境仍未验收。
